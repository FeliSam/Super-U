1) ÉTAT ACTUEL DU PERSONNEL (SOURCE DE VÉRITÉ)

1.1 Table ops.staff (server/src/schema-ops.sql)
  id TEXT PK
  email TEXT UNIQUE NOT NULL
  phone TEXT UNIQUE NOT NULL
  password_hash TEXT NOT NULL     -- scrypt:salt:hash (server/src/password.ts)
  first_name, last_name TEXT
  role TEXT NOT NULL DEFAULT 'coursier'
    CHECK (role IN ('picker', 'courier', 'coursier', 'dispatcher', 'both'))
  can_pick BOOLEAN NOT NULL DEFAULT TRUE
  can_deliver BOOLEAN NOT NULL DEFAULT TRUE
  CONSTRAINT staff_can_act_chk CHECK (can_pick OR can_deliver)
    ← BLOQUE admin / recruteur / support qui ne ramassent pas.
      À ÉLARGIR dans ce chantier (voir §3).
  store_id TEXT NULL              -- démo 'su-aeroport' (public.stores.id)
  vehicle TEXT NULL CHECK (moto | voiture | velo | pied)
  is_active BOOLEAN NOT NULL DEFAULT TRUE
  created_at TIMESTAMPTZ

1.2 Sessions
  ops.staff_sessions (token PK, staff_id FK, created_at)
  Login actuel : POST /ops/login  { email|phone|identifier, password }
  GET /ops/me
  Token Bearer. Utilisé par CourseGO (StaffAuthContext) ET comms.

1.3 Rôles SQL d’aujourd’hui (trop pauvres)
  picker      intention : ramassage seul
  courier     intention : livraison seule
  coursier    ramasse ET livre (démo ; rôle réel terrain)
  both        legacy, migré vers coursier si can_pick AND can_deliver
  dispatcher  prévu (affectation) — PAS d’UI admin ni d’API RH

  Les flags can_pick / can_deliver sont la VRAIE habilitation CourseGO :
    canPick  → GET/POST /ops/pick-jobs*
    canDeliver → /ops/deliveries*, /ops/location
  Un dispatcher actuel ne peut rien faire s’il a les deux flags false
  (interdit par staff_can_act_chk).

  same_handler : après pack, le même staff peut « LIVRER MAINTENANT »

2) VISION — RÔLES BIEN DÉFINIS (CONTRAT À IMPLÉMENTER)
================================================================================

Chaque personne a UN rôle principal (ops.staff.role) + flags d’habilitation
CourseGO (can_pick, can_deliver) + store_id + is_active.

Matrice (colonnes = ce que le compte a le droit de faire) :

Rôle            | Login CourseGO | Pick | Deliver | Admin catalogue | Admin RH | Disp. courses | Notes
----------------+----------------+------+---------+-----------------+----------+---------------+------
coursier        | oui            | oui  | oui     | non             | non      | non           | Défaut terrain (Koffi / Moussa)
picker          | oui            | oui  | non     | non             | non      | non           | Magasinier ramasseur
courier         | oui            | non  | oui     | non             | non      | non           | Livreur sans scan
dispatcher      | optionnel      | non  | non     | non             | non      | oui           | Affecte courses (futur board)
manager         | non*           | non  | non     | son magasin     | son magasin | son magasin | Chef de magasin
magasinier      | non            | non  | non     | stock son mag.  | non      | non           | Voir prompt catalogue
admin           | non            | non  | non     | tous magasins   | tous     | tous          | Siège
recruteur       | non            | non  | non     | non             | créer / onboarding | non | Pas de prix, pas d’ops live
support         | non            | non  | non     | non             | lecture  | non           | SAV interne (futur)

* manager : pas d’app moto, sauf si on pose can_pick pour dépanner — éviter
  par défaut.

Règles d’or rôles :
  1) role détermine le BACK-OFFICE. can_pick / can_deliver déterminent COURSEGO.
  2) recruteur PEUT créer un coursier mais NE PEUT PAS se donner role=admin.
  3) Un coursier NE PEUT PAS s’auto-promouvoir admin.
  4) Désactiver (is_active=false) révoque les sessions (DELETE staff_sessions).
  5) On ne SUPPRIME pas un staff lié à des livraisons : on archive
     (is_active=false). FK ON DELETE RESTRICT sur courses.
  6) store_id obligatoire pour picker, courier, coursier, magasinier, manager.
     admin / recruteur / support : store_id NULL = national.
  7) vehicle obligatoire si can_deliver (moto par défaut Cotonou).
  8) Email + téléphone uniques. Téléphone format +229 …

« Recruteur » — parcours cible :
  A. Crée la fiche (identité, tel, email, magasin visé, rôle cible).
  B. Statut onboarding : draft → invited → active
     (invite = mot de passe temporaire ou code à 6 chiffres, à changer
     à la 1re connexion CourseGO).
  C. Coche documents reçus (permis A/B, CIP, RIB plus tard).
  D. Un manager ou admin PASSE is_active=true et can_* définitifs.
  E. Le recruteur ne voit pas le chiffre d’affaires ni le catalogue prix.

« Dispatcher » (préparer le modèle, UI minimale OK) :
  - Voit les files pick/delivery du magasin (lecture /ops déjà filtrée store).
  - N’est PAS le même écran que le RH. Si tu n’as pas le temps du board
    dispatcher, crée le rôle + 403 propre, documente « board plus tard ».

================================================================================

Préfixe /admin/staff  Bearer
Garde : requireHr(staff) =
  admin | recruteur | manager (manager filtré sur store_id)

  GET    /admin/staff?q=&role=&storeId=&active=1|0&onboard=
  GET    /admin/staff/:id          (jamais password_hash)
  POST   /admin/staff              créer
         body : { email, phone, firstName, lastName, role, storeId,
                  canPick, canDeliver, vehicle, temporaryPassword? }
         Recruteur : role cible ∈ {picker, courier, coursier} seulement
         Admin : tous les rôles sauf s’auto-rétrograder s’il est le dernier admin
  PATCH  /admin/staff/:id          identité, rôle, flags, store, vehicle, notes
  POST   /admin/staff/:id/disable  is_active=false, onboard=suspended, wipe sessions
  POST   /admin/staff/:id/enable
  POST   /admin/staff/:id/reset-password  { temporaryPassword } + must_reset_password
  POST   /admin/staff/:id/documents       (niveau 2)
  GET    /ops/login reste INCHANGÉ pour CourseGO
  PATCH  /ops/me/password  (si must_reset_password) — utile 1re connexion

Dérivation flags si le client RH envoie seulement role (serveur autoritaire) :
  coursier → can_pick=true,  can_deliver=true,  vehicle défaut moto
  picker   → can_pick=true,  can_deliver=false, vehicle null
  courier  → can_pick=false, can_deliver=true,  vehicle moto
  dispatcher, manager, magasinier, admin, recruteur, support →
             can_pick=false, can_deliver=false
  Interdire can_deliver=true sans vehicle.
  Interdire role=coursier avec can_pick XOR can_deliver (incohérent).

Login CourseGO : refuser is_active=false et onboard_status ≠ 'active'
avec message clair « Compte non activé, voir le magasin / RH ».
