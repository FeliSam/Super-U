1) ÉTAT ACTUEL DU CATALOGUE (NE PAS IGNORER)
================================================================================

1.1 Postgres — tables minces, vérité dans JSONB
  public.products    (id TEXT PK, category_id TEXT NOT NULL, payload JSONB NOT NULL)
  public.categories  (id TEXT PK, payload JSONB NOT NULL)
  public.banners     (id TEXT PK, payload JSONB NOT NULL)
  public.chips       (id TEXT PK, payload JSONB NOT NULL)
  public.stores      (id TEXT PK, payload JSONB NOT NULL)

  Seed : server/src/seed.ts lit server/data/catalog.json (INSERT ON CONFLICT DO NOTHING).
  Dump  : scripts serveur dump-catalog.mjs. Export schéma : server/schema/00-public.sql

1.2 Payload produit (aujourd’hui)
  Champs observés dans catalog.json + type Product (marche-dore/data/catalog.ts) :
    id, name, unit, price (INT Fcfa), oldPrice?, discount? (ex. "-20%"),
    categoryId, producer?, description?, inStock? (BOOLEAN, défaut true),
    badge? ('nouveau' | 'local' | 'rupture'), rating?, reviews?,
    nutrition? { energy, protein, fat, carbs }
  IL N’Y A PAS encore : quantité en stock, SKU EAN, coût d’achat, TVA,
  stock par magasin, seuil d’alerte, lot / DLC.

  Rupture actuelle = inStock: false ET souvent badge: 'rupture'
  (ex. id "gingembre"). La boutique filtre inStockOnly via inStock !== false.

1.3 Double source images (IMPORTANT)
  - Fichiers locaux : marche-dore/assets/images/catalog/{id}.png
    (et cat-*.png pour rayons). Bundlés dans marche-dore/data/catalog.ts via require().
  - API GET /catalog/media/:id sert le PNG depuis ce dossier (server/src/productMedia.ts).
  - CourseGO : lib/catalogImages.generated.ts généré par
    SuperU/scripts/gen-catalog-images.mjs (npm run catalog:map à la racine).
  - hydrateCatalog.ts (boutique) : overlay prix/stock/texte depuis API ou SQLite
    SUR le catalogue local. JAMAIS d’image ni d’URL API. JAMAIS supprimer un SKU
    bundlé. restoreBundledCatalogImages() après overlay.

  Conséquence admin : un nouveau produit n’apparaît PAS correctement dans les
  apps mobiles tant que :
    a) la ligne Postgres existe,
    b) un PNG {id}.png est dans marche-dore/assets/images/catalog/,
    c) catalog.ts (boutique) ET catalogImages.generated.ts (CourseGO) sont
       régénérés / mis à jour.
  Phase 1 du dashboard : CRUD payload Postgres + flag inStock (les apps
  hydratent les SKU déjà bundlés). Phase 2 : upload image + script generate
  + documenter le rebuild Metro.

1.4 Lecture API actuelle (pas d’écriture catalogue)
  GET /catalog  → { products, categories, banners, chips }  PUBLIC
  GET /catalog/media/:id  → image
  GET /health
  Aucun PATCH /admin/products aujourd’hui. À AJOUTER dans server/src/index.ts
  (ou module server/src/admin.ts registerAdminRoutes).

1.5 Magasins (public.stores.payload)

2) VISION (CE QUE LE DASHBOARD DOIT DEVENIR)
================================================================================

Niveau A — immédiat (MVP, coller à l’existant)
  - Liste produits : recherche, filtre catégorie, filtre en stock / rupture.
  - Fiche : nom, unité, prix, oldPrice, discount, producer, description,
    badge, inStock, nutrition, categoryId.
  - Toggle rupture (inStock false + badge rupture) / retour en rayon.
  - Catégories : titre (payload), pas forcément les images (bundlées).
  - Bannières home : texte / ids existants (images bundlées).
  - Audit simple : qui a changé le prix, quand (ops.events ou table
    public.catalog_audit).

Niveau B — stock réel
  Nouvelle table (MÊME base, schéma public ou ops — préférer public) :
    public.product_stock (
      product_id TEXT REFERENCES products(id),
      store_id   TEXT REFERENCES stores(id),  -- ou TEXT aligné sur stores.id
      qty        NUMERIC(12,3) NOT NULL DEFAULT 0,  -- kg / pièces selon unit
      reserved   NUMERIC(12,3) NOT NULL DEFAULT 0,  -- paniers / commandes non packées
      min_qty    NUMERIC(12,3) NOT NULL DEFAULT 0,  -- seuil alerte
      updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      PRIMARY KEY (product_id, store_id)
    )
    public.stock_moves (
      id, product_id, store_id, delta, reason
        chk ('receipt','sale','adjust','shrink','pick_unavailable','transfer'),
      ref_type TEXT,  -- 'order' | 'admin' | 'pick_job'
      ref_id TEXT,
      actor_staff_id TEXT REFERENCES ops.staff(id),
      created_at
    )
  Règles :
    - inStock dérivé : qty - reserved > 0 (sync payload.inStock à chaque
      mouvement pour ne pas casser hydrateCatalog).
    - Réservation : à la confirmation de commande (status confirmed),
      reserved += qty lignes. Au pack / shipped : reserved -= , qty -= .
    - Si stock insuffisant au checkout : 409 clair, pas de survente silencieuse.
    - Transfert entre su-aeroport et su-ganhi = 2 moves.

Niveau C — catalogue vivant
  - Création SKU : id slug kebab-case unique (ex. mangues-kent), categoryId
    obligatoire, image upload →
    marche-dore/assets/images/catalog/{id}.png + npm run catalog:map
    + note « rebuild Expo ».
  - Code-barres (EAN-13 / code interne) pour ScanSheet CourseGO
    (aujourd’hui productBarcode() est dérivé de l’id).
  - Multi-unités plus tard (caisse vs kg) : hors MVP sauf si déjà dans unit.

4) API À AJOUTER (server/)
================================================================================

Préfixe /admin/*  (Bearer staff)

  GET    /admin/me
  GET    /admin/products?q=&categoryId=&stock=all|in|out&storeId=
  GET    /admin/products/:id
  PATCH  /admin/products/:id
         body : champs payload autorisés (whitelist). Interdit d’écraser id.
         Recalcule discount si oldPrice + price.
         Si inStock false → badge 'rupture' ; si true et badge rupture → retirer.
  POST   /admin/products
         body : { id, categoryId, payload } — id kebab, unique.
  PATCH  /admin/categories/:id
  GET    /admin/stores
  GET    /admin/stock?storeId=          (niveau B)
  POST   /admin/stock/moves             (niveau B)
  POST   /admin/products/:id/image      multipart PNG/WebP → fichier catalog
         (niveau C ; valider taille, pas de SVG script)

GET /catalog public reste en lecture pour les apps. Après PATCH admin, le
prochain hydrate boutique voit les nouveaux prix. Pas de cache long côté API.

Ne PAS exposer password_hash. Ne PAS laisser PATCH /admin sans auth.

Validation :
  price >= 0 entier Fcfa
  categoryId ∈ catégories existantes
  unit string non vide
  name 2–120 caractères
